# 静态分析边界

所有关系方向为调用者 → 被调用者；入度/出度按不同函数计数，重复调用不重复计边。自递归保留。bindings 是回调传参/注册，不混入直接 calls。

| 语言 | 解析和支持 | 需要查看诊断的情况 |
|---|---|---|
| Python | 标准 ast，函数及 lambda、词法作用域、显式 import/别名、明确构造接收者 | self/cls 动态派发、反射、猴子补丁、星号导入、动态构造 |
| JS/TS/JSX/TSX | TypeScript compiler API，源码符号、import/别名、tsconfig paths、明确构造接收者、箭头/回调 | 仅有类型注解的动态方法、包装器返回值、动态属性、联合类型歧义 |
| Vue | compiler-sfc 提取 script/script setup，保持源码行号 | 模板事件及模板表达式不当作直接函数执行 |
| Java | Tree-sitter，包名、显式 import、构造、明确接收者、lambda、按参数数量筛选 | 同数量重载、接口/继承动态派发、反射、泛型推断 |
| C/C++ | Tree-sitter，定义、头文件声明/include、命名空间、明确接收者、C++ lambda | 宏、函数指针、虚方法、多义重载、编译条件和模板实例化 |
| Go | Tree-sitter，go.mod 模块、包导入别名、接收者、函数及 func literal | 接口动态派发、运行时反射、构建标签、闭包值传递 |

Java/C++ 不作为编译器级全程序分析器。可语法解析不等于所有调用都能唯一解析；无法确认的项保留表达式、文件行号和原因。没有编译目标项目，也没有执行它的构建脚本。

`.h` 在项目存在 C++ 实现文件时按 C++ 语法处理。项目外依赖不渲染为已确认项目函数。语法错误中止整次更新，防止不完整图覆盖旧版。

canonical v2 在此使用 `nodes + edges` 的代码图配置：树是 root → 文件 → 函数；depends 边是完整调用；bindings 单独列出。代码项目允许只有一个文件，不强制学习导图的 4–7 分支配额。XMind 是可视子集，不能拿完整 canonical 节点数直接要求 XMind 等量；校验依据导航记录验证可视关系加引用等于所有重点函数间的调用。
